## Contexto

O time de produto quer que o app cumprimente cada pessoa pelo nome na tela inicial. Parece trivial — até você ver o que chega do cadastro: nomes com espaços sobrando, tudo em maiúsculas, tudo em minúsculas, e às vezes nada.

Este exercício existe menos pelo problema e mais pelo **fluxo**: ler um teste que falha, entender o que ele espera, escrever o mínimo para passar e rodar de novo. Você vai repetir esse ciclo centenas de vezes daqui para a frente.

## Requisitos

Implemente `Saudacao.para(String nome)` no arquivo `java/m00-comece-aqui/starter/src/main/java/dev/trilhajava/m00/Saudacao.java`.

| Entrada | Saída esperada |
|---|---|
| `"Ana"` | `"Olá, Ana!"` |
| `"   Bruno  "` | `"Olá, Bruno!"` |
| `"maria clara"` | `"Olá, Maria Clara!"` |
| `"JOÃO"` | `"Olá, João!"` |
| `null`, `""`, `"   "` | `"Olá, visitante!"` |

## Regras

- Espaços no começo e no fim do nome são ignorados.
- Cada parte do nome começa com maiúscula e o resto fica em minúsculas.
- Ausência de nome (nulo, vazio ou só espaços) resulta em `"Olá, visitante!"`.
- O método **nunca** lança exceção.

## Como trabalhar

1. Rode os testes **antes** de mudar qualquer coisa. Todos vão falhar com `UnsupportedOperationException` — isso é o esperado.
2. Faça passar **um teste por vez**, começando pelo mais simples (`cumprimentaPeloNome`).
3. A cada mudança, rode de novo. Leia a mensagem de falha com atenção: o AssertJ mostra o valor esperado e o recebido.

## Desafios opcionais

- Nomes com partículas: `"ana de souza"` → `"Ana de Souza"` (preposições `da`, `de`, `do`, `dos`, `das`, `e` ficam em minúsculas). Escreva o teste antes de implementar.
- Nomes compostos com hífen: `"jean-luc"` → `"Jean-Luc"`.

### Por que assim

- **A checagem de `null` vem primeiro.** `nome == null || nome.isBlank()` usa o *curto-circuito* do `||`: se o nome for `null`, a segunda parte nem é avaliada, então não há `NullPointerException`.
- **`strip()` em vez de `trim()`.** Os dois removem espaços das pontas, mas `strip()` (Java 11+) entende todos os espaços Unicode. Em código novo, prefira `strip()`.
- **`Locale` explícito.** `toUpperCase()` sem argumento usa o idioma do sistema operacional — em turco, `"i".toUpperCase()` vira `"İ"`. Fixar `pt-BR` torna o resultado igual em qualquer máquina. Esse é um bug real que já derrubou sistemas em produção.
- **`StringBuilder` para montar texto em laço.** Concatenar `String` com `+` dentro de laço cria um objeto novo a cada volta; o `StringBuilder` reaproveita o mesmo buffer. Você vai ver o porquê na aula de Strings do módulo 01.

### Alternativa com `String.join`

Uma versão igualmente boa, trocando o `StringBuilder` por um array e `String.join`:

```java
String[] partes = nome.strip().toLowerCase(PT_BR).split("\\s+");
for (int i = 0; i < partes.length; i++) {
    partes[i] = partes[i].substring(0, 1).toUpperCase(PT_BR) + partes[i].substring(1);
}
return "Olá, " + String.join(" ", partes) + "!";
```

No módulo 04, com Streams, isso vira uma única expressão.

### Avalie sua solução

- Seu código trata `null` sem exceção?
- Você chamou `toLowerCase()`/`toUpperCase()` com `Locale`? Se não, é um ponto de melhoria — não um erro grave.
- Cada método tem uma responsabilidade clara? Extrair um `capitalizar(String)` privado deixa o método principal legível.
