## Contexto

Um blog técnico usa URLs como `/posts/42`. O time de marketing quer URLs legíveis e boas para SEO, como `/posts/java-25-o-que-mudou`. Esse trecho final é o **slug**, e ele precisa ser gerado automaticamente a partir do título de cada post.

Parece simples até aparecerem títulos reais: `"Ação, Reação & Opção"`, `"---Já    tem   hífens---"`, `"Café_com_pão"`, e títulos enormes que geram URLs de 200 caracteres.

## O que você vai praticar

- **`String` é imutável; `StringBuilder` monta texto aos pedaços.** Todo método de `String` (`toLowerCase`, `substring`...) devolve uma **nova** string. Para construir um resultado caractere a caractere dentro de um laço, use um `StringBuilder`: `append(c)` acrescenta, `length()` e `charAt(i)` consultam, `isEmpty()` diz se ainda está vazio. Veja [Montando texto](../../../aulas/01-java-essencial/05-arrays-e-strings/#montando-texto).
- **Percorrer uma `String` com `for-each`.** `for (char c : texto.toCharArray())` visita cada caractere, em ordem. O índice não importa aqui, então o `for-each` é mais legível que o `for` clássico. Veja [Laços](../../../aulas/01-java-essencial/03-lacos/).
- **`char` é um número.** Por isso `c >= 'a' && c <= 'z'` testa se `c` é uma letra minúscula sem acento, e `c >= '0' && c <= '9'` testa se é um dígito. Com `&&` e `||` e parênteses, você monta a condição "é letra **ou** dígito". Veja [Operadores e decisões](../../../aulas/01-java-essencial/02-operadores-e-decisoes/).
- **Unicode e acentos (`java.text.Normalizer`).** Em Unicode, `á` pode ser um único caractere ou `a` seguido de um **acento combinante** separado. `Normalizer.normalize(texto, Normalizer.Form.NFD)` converte para a forma separada; depois, `Character.getType(c) == Character.NON_SPACING_MARK` identifica os acentos soltos, que você simplesmente não copia. Este é o único conceito que não está nas aulas: a explicação acima e a dica 2 bastam.
- **`toLowerCase(Locale.ROOT)`.** Sem o `Locale`, o resultado depende do idioma do computador (em turco, `"I".toLowerCase()` não é `"i"`). Slugs são identificadores técnicos e precisam dar o mesmo resultado em qualquer servidor. Veja [`String`: imutável por design](../../../aulas/01-java-essencial/05-arrays-e-strings/#string-imutável-por-design).

## Requisitos

Implemente, na classe `GeradorSlug` (pacote `dev.trilhajava.m01`, já criada no código inicial):

```java
public static final int TAMANHO_MAXIMO = 60;

public static String gerar(String titulo)
```

- **Recebe** o título de um post (pode ser `null`).
- **Devolve** o slug, seguindo as regras abaixo.
- **Lança** `IllegalArgumentException` quando não há slug possível (regra 6). A mensagem é livre.

| Título | Slug |
|---|---|
| `Olá Mundo` | `ola-mundo` |
| `Java 25: o que mudou?` | `java-25-o-que-mudou` |
| `Ação, Reação & Opção` | `acao-reacao-opcao` |
| `---Já    tem   hífens---` | `ja-tem-hifens` |
| `Café_com_pão` | `cafe-com-pao` |
| `ÇÃO Ñandú Über` | `cao-nandu-uber` |

## Regras

1. **Tudo em minúsculas.** `"JAVA Moderno"` → `java-moderno`.
2. **Acentos removidos, a letra fica.** `á` → `a`, `ç` → `c`, `ñ` → `n`, `ü` → `u`. `"ÇÃO Ñandú Über"` → `cao-nandu-uber`.
3. **Só `a`–`z` e `0`–`9` ficam.** Qualquer **sequência** de outros caracteres (espaço, pontuação, `_`, `&`, hífen...) vira **um único** hífen. `"Java 25: o que mudou?"` → `java-25-o-que-mudou` (o `": "` virou um hífen só); `"Café_com_pão"` → `cafe-com-pao`.
4. **Sem hífen no começo nem no fim.** `"---Já    tem   hífens---"` → `ja-tem-hifens`; `"  Olá Mundo!  "` → `ola-mundo`.
5. **No máximo 60 caracteres (`TAMANHO_MAXIMO`), sem cortar palavra no meio.** Se o slug passar de 60, fique com as **palavras inteiras** que cabem nos 60 primeiros caracteres (sem o hífen que sobraria no fim):
   | Título | Slug |
   |---|---|
   | `Como resolver o problema de N mais um no Hibernate sem perder a sanidade mental` | `como-resolver-o-problema-de-n-mais-um-no-hibernate-sem` (54) |
   | `Um guia completo de testes automatizados com JUnit e Mockito para quem está começando` | `um-guia-completo-de-testes-automatizados-com-junit-e-mockito` (60: `mockito` termina exatamente no limite e cabe inteira) |
   | `a` repetido 80 vezes | `a` repetido 60 vezes (uma palavra única maior que 60 é cortada em 60) |
6. **Sem nenhuma letra ou dígito, não há slug:** `null`, `""`, `"   "`, `"!!!"` e `"—"` (travessão, que não é o hífen `-`) lançam `IllegalArgumentException`.

## Passo a passo sugerido

Faça uma regra de cada vez e experimente depois de cada passo. Os casos das regras que você ainda não fez vão sair errados, e tudo bem: olhe só a regra em que está trabalhando.

1. **Monte um jeito de experimentar.** Crie, no mesmo pacote, uma classe sua com `main` que chama `GeradorSlug.gerar` com os títulos deste enunciado e imprime o resultado (há um exemplo em **Experimente**, logo abaixo). Rode com o ▶ do IntelliJ ao lado do `main`.
2. **Regras 1 e 3 (o esqueleto).** Converta o título para minúsculas, percorra os caracteres e copie para um `StringBuilder` só as letras `a`–`z` e os dígitos; para os outros, anexe um `'-'`. Experimente: `JAVA Moderno` já deve virar `java-moderno`, mas `Java 25: o que mudou?` ainda sai com hífens repetidos (`java-25--o-que-mudou-`).
3. **Regras 3 e 4 (hífens bem colocados).** Troque "anexe um hífen" por "anexe um hífen só **entre** dois trechos válidos". Uma forma: guarde numa variável `boolean` que apareceu um caractere inválido, e só anexe o hífen quando o **próximo** caractere válido chegar e o builder não estiver vazio. Os casos das regras 3 e 4 devem bater, exceto os títulos com acento.
4. **Regra 2 (acentos).** Antes do laço, aplique `Normalizer.normalize(titulo, Normalizer.Form.NFD)` e descarte os caracteres cujo `Character.getType(c)` é `Character.NON_SPACING_MARK`. Experimente: `Ação, Reação & Opção` → `acao-reacao-opcao`.
5. **Regra 6 (nada sobrou).** Se o título for `null`, ou se o builder terminar vazio, lance `IllegalArgumentException`. Os cinco casos da regra 6 devem lançar a exceção.
6. **Regra 5 (limite).** Se o slug tiver mais que `TAMANHO_MAXIMO` caracteres, corte. Pense nos três casos da tabela da regra 5: o que está logo **depois** do corte diz se a última palavra terminou no limite. Confira também o caso de exatamente 60.
7. **Brinque.** Acrescente seus próprios títulos: emojis, números, `"C++ & C#"`, um título só de acentos.

## Desafios opcionais

- **Uma passada só (reflexão).** Quantas vezes a sua solução percorre o título? Conte: `normalize`, `toLowerCase`, o seu laço... Dá para remover acentos, baixar a caixa e colocar os hífens no **mesmo** laço? Vale a pena, para títulos de 80 caracteres? (Resposta honesta: quase nunca. Legibilidade costuma ganhar.)

- **Stop words:** remova palavras como "o", "a", "de", "que" (`java-25-o-que-mudou` → `java-25-mudou`) e discuta o trade-off com legibilidade.

### Por que assim

- **NFD + `NON_SPACING_MARK`:** Unicode permite escrever `é` como um único caractere (U+00E9) ou como `e` + acento agudo combinante (U+0065 U+0301). `Normalizer.Form.NFD` converte tudo para a forma decomposta, e o laço descarta as marcas. Funciona para qualquer idioma com diacríticos, não só o português.
- **`hifenPendente`:** em vez de colocar o hífen quando aparece o caractere inválido (e depois ter de limpar repetições e pontas), a solução **adia** a decisão: o hífen só entra quando chega o próximo caractere válido. As regras 3 e 4 saem de graça.
- **`Locale.ROOT` no `toLowerCase`:** o mesmo cuidado do exercício 00.01. Slugs são identificadores técnicos: não podem depender do idioma do servidor.
- **Corte inteligente:** se o caractere logo **depois** do limite é um hífen, a palavra terminou exatamente em 60 e não há o que ajustar. Senão, recua até o último hífen dentro do limite; sem hífen nenhum, corta em 60.

### Alternativa: expressões regulares

Com regex, a solução fica mais curta. Ela **não** é necessária, mas vale conhecer:

```java
String semAcento = Normalizer.normalize(titulo, Normalizer.Form.NFD).replaceAll("\\p{M}", "");
String slug = semAcento.toLowerCase(Locale.ROOT)
        .replaceAll("[^a-z0-9]+", "-")   // qualquer sequência (+) de não (^) letra/dígito vira um hífen
        .replaceAll("^-|-$", "");        // tira um hífen do começo (^) ou do fim ($)
```

- `\p{M}` é a categoria Unicode *Mark* (todas as marcas combinantes; `NON_SPACING_MARK` é a principal delas). Em string Java, a barra é escrita duas vezes: `"\\p{M}"`.
- `[^a-z0-9]+`: os colchetes definem um conjunto de caracteres, o `^` dentro deles nega o conjunto, e o `+` pega "um ou mais seguidos".
- `^-|-$`: fora dos colchetes, `^` é o começo do texto e `$` o fim; `|` é "ou".

O custo: cada `replaceAll` percorre a string de novo, e uma regex errada falha em silêncio (produz um slug estranho em vez de um erro). Para quem está começando, o laço explícito é mais fácil de depurar com o seu programa.

### Um detalhe sobre `ß` e `Æ`

`"straße"` vira `"strae"`, porque o `ß` não tem decomposição NFD em `ss`. Para idiomas assim, existem bibliotecas de transliteração (como a ICU4J). Saber **onde a solução simples para de funcionar** é parte de ser Pleno.
