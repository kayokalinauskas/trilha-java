Antes de escrever código, você precisa de quatro ferramentas: o **JDK** (para compilar e rodar Java), o **Maven** (para gerenciar dependências e rodar testes), o **Git** (para versionar) e uma **IDE** (para escrever com produtividade). Esta aula mostra como instalar cada uma e, mais importante, **o que cada uma faz**.

1. O **compilador** (`javac`) lê o arquivo `.java`, verifica tipos e sintaxe e gera **bytecode** (`.class`) — um formato intermediário, independente de sistema operacional.
2. A **JVM** (Java Virtual Machine) carrega esse bytecode e o executa. Trechos muito usados são compilados para código de máquina nativo em tempo de execução pelo **JIT** (*Just-In-Time compiler*) — é por isso que aplicações Java ficam mais rápidas depois de "aquecer".

Os nomes que aparecem em toda vaga:

| Sigla | O que é | Você precisa? |
|---|---|---|
| **JVM** | A máquina virtual que executa bytecode | Vem dentro do JDK |
| **JRE** | "Java Runtime Environment": JVM + bibliotecas, só para executar | Não existe mais como download separado desde o Java 11 |
| **JDK** | "Java Development Kit": JRE + compilador + ferramentas (`javac`, `jshell`, `jar`…) | **Sim** — é o que você instala |

<Callout tipo="entrevista">
"Qual a diferença entre JDK, JRE e JVM?" é uma pergunta clássica de triagem Júnior. Responda com o fluxo: **o JDK compila (`javac`) o código em bytecode, e a JVM executa esse bytecode**; o JRE era o pacote só de execução. Mencionar o JIT mostra que você entende por que Java é rápido apesar de ser "interpretado".
</Callout>

## Qual versão do Java usar?

O Java lança uma versão nova a cada 6 meses (março e setembro). A cada dois anos, uma delas é **LTS** (*Long-Term Support*), com anos de correções de segurança. Empresas praticamente só usam LTS.

| Versão | Lançamento | Situação em 2026 |
|---|---|---|
| Java 8 | 2014 | Ainda presente em sistemas legados (bancos, governo). Vale saber ler. |
| Java 11 | 2018 | Legado em migração. |
| Java 17 | 2021 | Muito usado; mínimo exigido pelo Spring Boot 3 e 4. |
| Java 21 | 2023 | Muito usado; trouxe **virtual threads** e pattern matching completo. |
| **Java 25** | **set/2025** | **LTS atual.** É o que esta trilha usa. |

Nesta trilha você vai usar o **Java 25**. Tudo o que aprender funciona no 21, e as diferenças são sinalizadas com o selo "Java moderno" quando aparecerem.

## Instalando o JDK 25

Existem várias distribuições do mesmo OpenJDK (Eclipse Temurin, Amazon Corretto, Azul Zulu, Oracle OpenJDK…). Para estudar, qualquer uma serve. Recomendamos **Eclipse Temurin**, gratuita e amplamente usada.

<Tabs grupo="so">
<Tab rotulo="Windows">

A forma mais simples é pelo **winget**, o gerenciador de pacotes que já vem no Windows 10/11. Abra o **Terminal** (ou PowerShell) e rode:

```powershell
winget install EclipseAdoptium.Temurin.25.JDK
```

O instalador configura o `PATH` e o `JAVA_HOME`. **Feche e abra o terminal de novo** para as variáveis valerem.

</Tab>
<Tab rotulo="macOS">

Recomendamos o **SDKMAN!**, que permite ter várias versões do Java e trocar entre elas com um comando:

```bash
curl -s "https://get.sdkman.io" | bash
# abra um novo terminal
sdk list java | grep -- "-tem"      # veja o identificador exato do 25 (ex.: 25.0.2-tem)
sdk install java 25.0.2-tem         # use o identificador que apareceu na lista
```

Alternativa com Homebrew: `brew install --cask temurin@25`.

</Tab>
<Tab rotulo="Linux">

O **SDKMAN!** funciona igual ao macOS e é a opção mais prática:

```bash
curl -s "https://get.sdkman.io" | bash
# abra um novo terminal
sdk list java | grep -- "-tem"      # veja o identificador exato do 25 (ex.: 25.0.2-tem)
sdk install java 25.0.2-tem         # use o identificador que apareceu na lista
```

Em distribuições Debian/Ubuntu também é possível usar o repositório da Adoptium com `apt`.

</Tab>
</Tabs>

Verifique:

```bash
java -version
javac -version
```

A saída deve mencionar a versão `25`. Se aparecer outra versão, você tem mais de um JDK instalado e o `PATH` está apontando para o antigo — veja a seção de problemas comuns no fim da aula.

## A IDE: IntelliJ IDEA

A IDE mais usada no mercado Java é o **IntelliJ IDEA**. A edição gratuita atende tudo o que você precisa nesta trilha. Baixe pelo site da JetBrains ou pelo **JetBrains Toolbox**, que também mantém a IDE atualizada.

<Callout tipo="dica" titulo="Três atalhos para aprender já no primeiro dia">

- <kbd>Alt</kbd> + <kbd>Enter</kbd> (<kbd>⌥</kbd> + <kbd>↩</kbd> no Mac) — "conserte isso para mim": importa classes, cria métodos, sugere correções.

## Baixando o projeto da trilha

Todos os exercícios ficam na pasta `java/` do repositório da trilha:

```bash
git clone https://github.com/kayokalinauskas/trilha-java.git
cd trilha-java/java
mvn -q verify
```

O `mvn verify` baixa as dependências (só na primeira vez), compila e roda os testes das **soluções de referência**. Se terminar sem erros, seu ambiente está pronto.

Para fazer um exercício no IntelliJ, abra **o starter do módulo** como projeto: **File → Open**, selecione o `pom.xml` da pasta `java/<módulo>/starter` (por exemplo, `java/m01-java-essencial/starter/pom.xml`) e escolha **Open as Project**. Ele importa o projeto Maven, incluindo a pasta `testes` ao lado. Em **File → Project Structure**, confira se o SDK é o JDK 25. Não abra a pasta `java/` inteira para fazer exercícios: ali o IntelliJ carrega as **soluções** e deixa os starters de fora.

<Callout tipo="info" titulo="Ainda está no Java 21?">
Os módulos 00 a 03 funcionam no 21. Rode com `mvn -q verify -Djava.release=21` enquanto não atualiza.
</Callout>

## Problemas comuns

| Sintoma | Causa provável | Solução |
|---|---|---|
| `'java' não é reconhecido como comando` | O terminal foi aberto antes da instalação | Feche e abra o terminal (ou reinicie o computador no Windows) |
| `java -version` mostra 17 ou 21 | Outro JDK vem antes no `PATH` | Windows: ajuste `JAVA_HOME` e `PATH` em "Variáveis de ambiente". SDKMAN: `sdk default java <identificador-do-25>` |
| `mvn -v` mostra um Java diferente de `java -version` | `JAVA_HOME` aponta para outro JDK | Corrija o `JAVA_HOME` para a pasta do JDK 25 |
| `release version 25 not supported` | O Maven está usando um JDK antigo | Mesmo caso acima |
| Acentos aparecem como `Ã§` no terminal do Windows | Codificação do console | Rode `chcp 65001` antes, ou use o terminal do IntelliJ |
| O IntelliJ abre o projeto, mas a árvore fica vazia (só "External Libraries") | A importação Maven ficou corrompida | Feche o IntelliJ, apague a pasta `.idea` dentro do starter e abra de novo pelo `pom.xml` (**Open as Project**) |

## Resumo

- Você escreve `.java`, o `javac` gera bytecode `.class` e a **JVM** executa — em qualquer sistema.
- Instale sempre o **JDK**. Nesta trilha, o **JDK 25 (LTS)**.
- Maven, Git e IntelliJ completam o kit. Verifique cada um com `java -version`, `mvn -v` e `git --version`.
- `mvn -q verify` na pasta `java/` confirma que está tudo funcionando.
