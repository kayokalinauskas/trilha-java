Um método é uma **unidade de comportamento com nome**. Um bom método faz uma coisa só, tem um nome que diz o quê, e pode ser entendido sem ler o resto do código. Isso parece estética, mas é engenharia: código é lido dez vezes mais do que é escrito, e quem lê é o seu time (e você mesmo, daqui a seis meses).

## Anatomia

```java
public static BigDecimal calcularParcela(BigDecimal total, int parcelas) {
    return total.divide(BigDecimal.valueOf(parcelas), 2, RoundingMode.HALF_EVEN);
}
```

| Parte | Neste exemplo |
|---|---|
| Modificador de acesso | `public` (quem pode chamar) |
| `static` | pertence à classe, não a um objeto |
| Tipo de retorno | `BigDecimal` (ou `void`, se não devolve nada) |
| Nome | `calcularParcela` — verbo no infinitivo, em *camelCase* |
| Parâmetros | `(BigDecimal total, int parcelas)` |
| Corpo | entre chaves |

A **assinatura** é o nome junto com os tipos dos parâmetros: `calcularParcela(BigDecimal, int)`.

## Nomes que se explicam

Convenções que o mercado segue:

- Métodos são **verbos** (`calcular`, `buscar`, `enviar`). Métodos que devolvem `boolean` costumam começar com `eh`/`is`, `tem`/`has`, `pode`/`can`.
- Nada de abreviações que só você entende. O nome longo e claro ganha do curto e ambíguo.
- Se o nome precisa de "e" (`validarESalvar`), o método provavelmente faz duas coisas.

## Parâmetros: sempre por valor

Esta é uma das perguntas mais clássicas de entrevista Java. A resposta curta: **Java sempre passa por valor**. A longa é o que confunde:

```java
void zerar(int numero) {
    numero = 0;              // altera a CÓPIA
}

int saldo = 100;
zerar(saldo);
System.out.println(saldo);   // 100
```

Com objetos, o "valor" copiado é a **referência** (o "endereço" do objeto). As duas variáveis apontam para o **mesmo objeto**:

```java
void adicionarItem(List<String> itens) {
    itens.add("brinde");     // altera o objeto apontado: visível lá fora
    itens = new ArrayList<>(); // troca só a cópia da referência: invisível lá fora
}

List<String> carrinho = new ArrayList<>(List.of("café"));
adicionarItem(carrinho);
System.out.println(carrinho); // [café, brinde]
```

A consequência prática: **métodos podem modificar os objetos que recebem**. Isso é poderoso e perigoso. Por isso, no módulo 02, você vai aprender a proteger objetos com imutabilidade e cópias defensivas.

## Retorno e efeitos colaterais

Um método pode **devolver um resultado** ou **causar um efeito** (alterar um objeto, gravar no banco, enviar um e-mail). Os que só devolvem resultado, sem efeitos, são chamados de **funções puras**, e são os mais fáceis de testar e de entender:

```java
// Pura: mesmo input, mesmo output, nenhum efeito
static BigDecimal comDesconto(BigDecimal preco, BigDecimal percentual) {
    return preco.subtract(preco.multiply(percentual));
}
```

Todos os exercícios do módulo 01 são funções puras. Não é coincidência: elas são o melhor lugar para começar a testar.

<Callout tipo="atencao">
Evite métodos que **fingem** ser consultas mas alteram estado, como um `getSaldo()` que também registra auditoria no banco. Quem lê o nome não espera o efeito colateral.
</Callout>

## Sobrecarga (overload)

Vários métodos com o **mesmo nome** e **parâmetros diferentes**:

```java
static BigDecimal reais(String valor)  { return new BigDecimal(valor); }
static BigDecimal reais(long centavos) { return BigDecimal.valueOf(centavos, 2); }

reais("19.90");   // chama a versão String
reais(1990L);     // chama a versão long
```

O compilador escolhe qual chamar **em tempo de compilação**, olhando os tipos dos argumentos. O tipo de retorno **não** diferencia sobrecargas. Use com moderação: duas sobrecargas que fazem coisas diferentes confundem.

## `static` ou não?

- Métodos **de instância** usam o estado do objeto (`conta.sacar(valor)` usa o saldo daquela conta).
- Métodos **`static`** não dependem de nenhum objeto (`Math.max(a, b)`, `Integer.parseInt(s)`).

Neste módulo, todos os exercícios usam `static` porque são funções puras sobre os parâmetros. A partir do módulo 02, o comportamento passa a viver **dentro dos objetos**, e `static` vira exceção.

## Escopo de variáveis

Uma variável existe do ponto em que é declarada até o fim do bloco (`{ }`) que a contém:

```java
for (int i = 0; i < 3; i++) {
    String rotulo = "item " + i;
}
System.out.println(i);       // não compila: i não existe aqui
```

Declare variáveis **o mais perto possível de onde são usadas** e com o menor escopo possível. Menos coisas "vivas" ao mesmo tempo significa menos para manter na cabeça.

## Refatorando um método longo

Métodos longos misturam níveis de abstração. Veja uma rotina que valida e formata um telefone:

<Comparar antes="Tudo junto" depois="Um nível por método">
```java
static String formatarTelefone(String t) {
    if (t == null) throw new IllegalArgumentException();
    String d = "";
    for (char c : t.toCharArray())
        if (Character.isDigit(c)) d += c;
    if (d.length() != 10 && d.length() != 11)
        throw new IllegalArgumentException();
    if (d.length() == 11)
        return "(" + d.substring(0,2) + ") "
            + d.substring(2,7) + "-" + d.substring(7);
    return "(" + d.substring(0,2) + ") "
        + d.substring(2,6) + "-" + d.substring(6);
}
```

```java
static String formatarTelefone(String telefone) {
    String digitos = somenteDigitos(telefone);
    exigirTamanhoValido(digitos);
    return ehCelular(digitos)
            ? mascarar(digitos, 7)
            : mascarar(digitos, 6);
}

static boolean ehCelular(String digitos) {
    return digitos.length() == 11;
}
// somenteDigitos, exigirTamanhoValido, mascarar...
```
</Comparar>

A versão da direita se lê como uma receita: limpa, valida e formata. Cada detalhe mora num método pequeno com nome próprio, que pode ser testado sozinho.

## Resumo

- Um método, uma responsabilidade, um nome que diz o quê.
- Java **sempre passa por valor**; para objetos, o valor é a referência.
- Prefira funções puras quando possível: são fáceis de testar.
- Sobrecarga é resolvida na compilação; o retorno não diferencia sobrecargas.
- Métodos longos viram vários métodos pequenos, cada um em um nível de abstração.
