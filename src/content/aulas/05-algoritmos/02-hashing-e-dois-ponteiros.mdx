Se você só pudesse aprender uma técnica de otimização, seria esta: **quando você procura algo repetidamente numa lista, guarde o que já viu num `HashMap` ou `HashSet`**. A busca cai de O(n) para O(1), e o algoritmo inteiro de O(n²) para O(n).

## O clássico: Two Sum

> Dado um array de valores e um alvo, encontre os índices de dois elementos que somam o alvo.

**Força bruta:** testar todos os pares, O(n²).

```java
for (int i = 0; i < v.length; i++)
    for (int j = i + 1; j < v.length; j++)
        if (v[i] + v[j] == alvo) return new int[] {i, j};
```

**Otimização:** para cada `v[j]`, a pergunta é "o **complemento** `alvo - v[j]` já apareceu antes?". Um `HashMap<valor, índice>` responde em O(1):

```java
Map<Long, Integer> vistos = new HashMap<>();
for (int j = 0; j < v.length; j++) {
    Integer i = vistos.get(alvo - v[j]);
    if (i != null) return new int[] {i, j};
    vistos.putIfAbsent(v[j], j);
}
return new int[0];
```

O(n) de tempo, O(n) de memória. É o exemplo mais citado de "trocar memória por tempo". O exercício 05.01 começa por ele, num cenário de auditoria de transações.

## Variações do "já vi isto?"

- **Duplicata a até k posições:** guarde a **última posição** de cada valor; ao revê-lo, compare a distância.
- **Primeiro elemento que não se repete:** conte com um `LinkedHashMap` (que preserva a ordem de chegada) e depois procure o primeiro com contagem 1.
- **Agrupar anagramas:** a chave do mapa é a palavra com as letras ordenadas.
- **Maior sequência de consecutivos** (`[100, 4, 200, 1, 3, 2]` → 4, de 1 a 4): ordenar resolve em O(n log n), mas dá para fazer O(n):

```java
Set<Integer> presentes = new HashSet<>(lista);
int maior = 0;
for (int x : presentes) {
    if (presentes.contains(x - 1)) continue;   // só conta a partir do INÍCIO de uma sequência
    int tamanho = 1;
    while (presentes.contains(x + tamanho)) tamanho++;
    maior = Math.max(maior, tamanho);
}
```

Parece O(n²) por causa do `while` dentro do `for`, mas **cada número é visitado no máximo duas vezes** (uma no `for`, uma no `while` da sequência a que pertence). Esse tipo de análise — contar quantas vezes cada elemento é tocado no total — se chama **análise amortizada** e impressiona em entrevista.

## Dois ponteiros

Quando o array está **ordenado**, dá para resolver muitos problemas de pares **sem memória extra**, com um ponteiro em cada ponta:

```java
// Array ORDENADO: existe par com soma = alvo?
int esq = 0, dir = v.length - 1;
while (esq < dir) {
    long soma = v[esq] + v[dir];
    if (soma == alvo) return true;
    if (soma < alvo) esq++;     // precisa de um valor maior
    else dir--;                 // precisa de um valor menor
}
return false;
```

A ordenação permite **descartar** metade das possibilidades a cada passo: se a soma está pequena, nenhum par com o `esq` atual e um `dir` menor vai funcionar, então só `esq` pode avançar.

Outros usos de dois ponteiros:

- **Remover duplicatas de um array ordenado no lugar** (um ponteiro lê, outro escreve).
- **Verificar palíndromo** (um de cada ponta, andando para o meio).
- **Mesclar duas listas ordenadas** (um ponteiro em cada lista — a base do *merge sort*).
- **Ponteiros rápido e lento** em listas encadeadas (detectar ciclo, achar o meio).

## Hash ou dois ponteiros?

| Abordagem | Tempo | Memória extra | Precisa de ordem? |
|---|---|---|---|
| Força bruta | O(n²) | O(1) | não |
| `HashMap` | O(n) | O(n) | não |
| Ordenar + dois ponteiros | O(n log n) | O(1)* | sim (ou ordena antes) |

\* sem contar a ordenação, se ela puder ser feita no lugar.

Detalhe importante: ordenar **perde os índices originais**. Se o problema pede os índices (como o Two Sum clássico), o hash é a escolha natural.

## Resumo

- "Procuro algo repetidamente?" → **`HashMap`/`HashSet`**: O(n²) vira O(n), ao custo de O(n) de memória.
- Two Sum: guarde valor → índice e procure o complemento.
- Array ordenado + pares → **dois ponteiros**, O(1) de memória extra.
- Análise amortizada: conte quantas vezes cada elemento é tocado no total.
