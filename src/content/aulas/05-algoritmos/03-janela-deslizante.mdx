Muitos problemas de negócio perguntam sobre **períodos contínuos**: "o maior intervalo de dias dentro do orçamento", "a média móvel de 7 dias", "o menor número de horas seguidas para bater a meta". A força bruta testa todos os trechos, O(n²) ou pior. A **janela deslizante** resolve em O(n) com dois índices que só andam para a frente.

## Janela de tamanho fixo

> Média móvel de k dias.

**Força bruta:** para cada posição, somar os k elementos. O(n × k).

**Janela:** a soma da janela seguinte é a soma atual **+ o que entra − o que sai**.

```java
double soma = 0;
for (int i = 0; i < valores.length; i++) {
    soma += valores[i];                 // entra
    if (i >= k) soma -= valores[i - k]; // sai
    if (i >= k - 1) medias[i - k + 1] = soma / k;
}
```

O(n), independentemente de k.

## Janela de tamanho variável

Quando o tamanho não é fixo, a janela **expande** pelo fim e **encolhe** pelo início conforme uma condição.

### Maior trecho que respeita uma condição

> Maior sequência de produtos visualizados sem repetir nenhum.

```java
Map<String, Integer> ultimaPosicao = new HashMap<>();
int inicio = 0, maior = 0;
for (int fim = 0; fim < produtos.length; fim++) {
    Integer anterior = ultimaPosicao.put(produtos[fim], fim);
    if (anterior != null && anterior >= inicio) {
        inicio = anterior + 1;          // pula para depois da repetição
    }
    maior = Math.max(maior, fim - inicio + 1);
}
```

Repare no `anterior >= inicio`: uma repetição que ficou **fora** da janela atual não importa.

### Menor trecho que atinge uma meta

> Menor número de horas seguidas cuja soma de vendas atinge a meta (valores positivos).

```java
int inicio = 0, menor = Integer.MAX_VALUE;
long soma = 0;
for (int fim = 0; fim < vendas.length; fim++) {
    soma += vendas[fim];                   // expande
    while (soma >= meta) {                 // enquanto a condição vale, tenta encolher
        menor = Math.min(menor, fim - inicio + 1);
        soma -= vendas[inicio++];
    }
}
return menor == Integer.MAX_VALUE ? 0 : menor;
```

### O molde geral

```text
para fim de 0 até n-1:
    incluir elemento[fim] no estado da janela
    enquanto a janela é inválida (ou pode melhorar):
        remover elemento[inicio] do estado; inicio++
    atualizar a resposta com a janela [inicio, fim]
```

O "estado da janela" pode ser uma soma, um contador de caracteres (`Map<Character, Integer>`), um conjunto…

## Por que é O(n), se tem um `while` dentro do `for`?

Porque `inicio` e `fim` **só avançam**, cada um no máximo n vezes. O total de passos do `while`, somado ao longo de toda a execução, é no máximo n. Tempo total: O(n) + O(n) = O(n). É a mesma análise amortizada da aula anterior — e você deve dizê-la em voz alta na entrevista, porque o entrevistador vai perguntar.

<Callout tipo="atencao" titulo="Números negativos quebram a janela">
A janela variável para "soma ≥ meta" depende de uma propriedade: **encolher a janela nunca aumenta a soma**. Com valores negativos, isso deixa de valer. Para "subarray com soma exatamente K" com negativos, a técnica é **soma de prefixos + HashMap** (guardar quantas vezes cada soma acumulada apareceu).
</Callout>

## Resumo

- **Trecho contíguo** + "maior/menor/com soma" → janela deslizante.
- Janela **fixa**: some o que entra, subtraia o que sai.
- Janela **variável**: expande pelo fim, encolhe pelo início enquanto a condição pede.
- É O(n) porque os ponteiros só avançam; com negativos, use soma de prefixos.
