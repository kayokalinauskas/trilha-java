Pilhas (LIFO: último a entrar, primeiro a sair) e filas (FIFO: primeiro a entrar, primeiro a sair) são estruturas simples que resolvem uma família grande de problemas — e aparecem no backend real, da pilha de chamadas da JVM às filas de mensageria do módulo 12.

## `ArrayDeque` para as duas

```java
Deque<Character> pilha = new ArrayDeque<>();
pilha.push('(');      // empilha no topo
pilha.peek();         // olha o topo
pilha.pop();          // tira do topo

Deque<String> fila = new ArrayDeque<>();
fila.offer("pedido-1");   // entra no fim
fila.peek();              // olha o início
fila.poll();              // sai do início (null se vazia)
```

<Callout tipo="atencao">
Não use `java.util.Stack`: é uma classe antiga, sincronizada e que herda de `Vector` (permite acesso por índice, o que quebra a abstração de pilha). A própria documentação da JDK recomenda `ArrayDeque`.
</Callout>

## Estruturas aninhadas: delimitadores balanceados

> `{"itens": [1, 2, {"x": (3)}]}` está balanceado? E `([)]`?

Cada abertura vai para a pilha; cada fechamento precisa casar com o **topo**:

```java
for (char c : expressao.toCharArray()) {
    if (c == '(' || c == '[' || c == '{') {
        pilha.push(c);
    } else if (FECHA_PARA_ABRE.containsKey(c)) {
        if (pilha.isEmpty() || !pilha.pop().equals(FECHA_PARA_ABRE.get(c))) return false;
    }
}
return pilha.isEmpty();   // sobrou alguém aberto?
```

Três formas de falhar: fechar sem ter aberto (pilha vazia), fechar o tipo errado (`([)]`) e terminar com algo aberto (`((`). Um bom conjunto de testes cobre as três.

<Callout tipo="erro" titulo="Character e ==">
`pilha.pop() != '('` compara um `Character` (objeto) com `==`. Funciona por causa do cache de caracteres ASCII, mas é o mesmo anti-padrão do `Integer ==` do módulo 01. Use `equals`.
</Callout>

## Pilha monotônica: "quantos dias até esquentar?"

> Para cada dia, quantos dias até uma temperatura maior? `[73, 74, 75, 71, 69, 72, 76, 73]` → `[1, 1, 4, 2, 1, 1, 0, 0]`

**Força bruta:** para cada dia, procurar à frente. O(n²).

**Pilha monotônica:** guarde os **índices** dos dias ainda "sem resposta", em ordem decrescente de temperatura. Quando chega um dia mais quente, ele **resolve** todos os dias mais frios do topo:

```java
Deque<Integer> pendentes = new ArrayDeque<>();
for (int hoje = 0; hoje < t.length; hoje++) {
    while (!pendentes.isEmpty() && t[hoje] > t[pendentes.peek()]) {
        int dia = pendentes.pop();
        resposta[dia] = hoje - dia;
    }
    pendentes.push(hoje);
}
```

Cada índice entra e sai da pilha **uma vez**: O(n). O mesmo padrão resolve "próximo menor preço", "maior retângulo em histograma" e "cotações até a próxima alta".

## Avaliando expressões

A **notação polonesa reversa** (RPN) coloca o operador depois dos operandos: `3 4 + 2 *` = `(3 + 4) * 2` = 14. Não precisa de parênteses nem de precedência, e é avaliada com uma pilha:

```text
token 3 → pilha [3]
token 4 → pilha [3, 4]
token + → tira 4 e 3, empilha 7 → [7]
token 2 → [7, 2]
token * → tira 2 e 7, empilha 14 → [14]
```

Cuidado com a **ordem** em `-` e `/`: o primeiro `pop` é o operando da **direita**. E valide: operador sem operandos suficientes ou sobra de valores no final indicam expressão malformada.

## Filas: processar na ordem de chegada

Filas aparecem sempre que o trabalho deve ser feito **na ordem em que chegou** ou **nível a nível**:

- a **BFS** (próxima aula) usa uma fila para visitar um grafo em camadas;
- um processador de tarefas pega o próximo da fila;
- `PriorityQueue` é a "fila com prioridade": sempre sai o menor (ou o de maior prioridade), em O(log n).

## Resumo

- `ArrayDeque`: `push/pop/peek` como pilha, `offer/poll/peek` como fila.
- Aninhamento, desfazer e expressões → **pilha**.
- "Próximo maior/menor" → **pilha monotônica**, O(n).
- Ordem de chegada e camadas → **fila**; prioridade → `PriorityQueue`.
