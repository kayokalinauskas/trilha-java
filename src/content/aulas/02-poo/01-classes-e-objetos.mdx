No módulo 01, todo o código viveu em métodos `static`: funções que recebem dados e devolvem resultados. Funciona bem para problemas pequenos. Mas um sistema real tem **conceitos** — conta, pedido, cliente, pagamento — e cada conceito tem **dados** e **regras**. Orientação a objetos é uma forma de organizar o código em torno desses conceitos.

## Classe é o molde; objeto é a coisa

```java
public class Produto {

    String nome;           // estado (atributos)
    BigDecimal preco;
    int estoque;

    boolean disponivel() { // comportamento (métodos)
        return estoque > 0;
    }
}
```

`Produto` é uma **classe**: descreve o que todo produto tem e sabe fazer. Um **objeto** é um produto específico, criado com `new`:

```java
Produto cafe = new Produto();
cafe.nome = "Café 500g";
cafe.preco = new BigDecimal("25.90");
cafe.estoque = 12;

Produto filtro = new Produto();
filtro.nome = "Filtro de papel";
filtro.estoque = 0;

cafe.disponivel();    // true
filtro.disponivel();  // false — mesmo método, estado diferente
```

Cada objeto tem **seu próprio estado**. O método `disponivel()` é o mesmo para todos, mas responde de acordo com os dados **daquele** objeto.

## Construtores: nascer pronto

O código acima tem um problema: dá para criar um `Produto` sem nome, sem preço, "pela metade". Um **construtor** garante que o objeto já nasce completo:

```java
public class Produto {

    private final String nome;
    private final BigDecimal preco;
    private int estoque;

    public Produto(String nome, BigDecimal preco, int estoqueInicial) {
        this.nome = nome;
        this.preco = preco;
        this.estoque = estoqueInicial;
    }
}

Produto cafe = new Produto("Café 500g", new BigDecimal("25.90"), 12);
```

- O construtor tem o **mesmo nome da classe** e **não tem tipo de retorno**.
- **`this.nome`** é o atributo do objeto; `nome` sozinho é o parâmetro. O `this` resolve a ambiguidade.
- Se você não escrever nenhum construtor, o Java cria um **vazio** automaticamente. Ao escrever um, o vazio deixa de existir.

Você pode ter vários construtores, e um pode chamar outro com `this(...)`:

```java
public Produto(String nome, BigDecimal preco) {
    this(nome, preco, 0);   // estoque padrão: zero
}
```

- A **stack** guarda as variáveis locais de cada chamada de método. Para primitivos, o próprio valor (`qtd = 12`); para objetos, **uma referência**.
- A **heap** guarda os objetos criados com `new`.
- `Produto outro = cafe;` **não copia** o produto. Cria uma segunda referência para o **mesmo** objeto. Alterar por uma variável é visível pela outra.
- Quando nenhuma referência aponta mais para um objeto, o **garbage collector** (GC) libera a memória automaticamente. Em Java você não faz `free`/`delete`.

<Callout tipo="entrevista">
"Explique stack e heap" e "como funciona o garbage collector?" aparecem em entrevistas Júnior e Pleno. Para Pleno, vale saber que a JVM moderna tem vários coletores (G1 é o padrão; ZGC e Shenandoah para pausas muito curtas) e que **vazamento de memória em Java** existe: acontece quando você mantém referências sem querer, por exemplo em um `static Map` que só cresce.
</Callout>

## `null`: a referência para nada

```java
Produto p = null;     // não aponta para nenhum objeto
p.disponivel();       // NullPointerException
```

Uma referência pode não apontar para nada. Tony Hoare, que inventou a referência nula em 1965, chamou isso de seu "erro de um bilhão de dólares". Ao longo da trilha você vai ver várias defesas: validar no construtor, nunca devolver `null` quando uma coleção vazia serve, e `Optional` (módulo 04).

## Comportamento junto dos dados

Veja duas formas de implementar "dar baixa no estoque":

<Comparar antes="Modelo anêmico" depois="Objeto com comportamento">
```java
// Em algum Service, longe do Produto:
if (produto.getEstoque() >= qtd) {
    produto.setEstoque(produto.getEstoque() - qtd);
} else {
    throw new EstoqueInsuficienteException();
}
```

```java
// Dentro de Produto:
public void baixarEstoque(int quantidade) {
    if (quantidade > estoque) {
        throw new EstoqueInsuficienteException(nome, estoque, quantidade);
    }
    estoque -= quantidade;
}

// Quem usa:
produto.baixarEstoque(qtd);
```
</Comparar>

Na versão da esquerda, a regra "não pode ficar negativo" vive **fora** do produto. Se outro lugar do código fizer `setEstoque(-5)`, nada impede. Na versão da direita, o **produto protege a própria regra**. Esse princípio tem nome: ***Tell, Don't Ask*** — diga ao objeto o que fazer, em vez de pedir os dados dele e decidir por ele.

A próxima aula aprofunda essa ideia: **encapsulamento e invariantes**.

## Resumo

- **Classe** define estado e comportamento; **objeto** é uma instância com estado próprio.
- **Construtores** garantem que o objeto nasce completo; `this` diferencia atributo de parâmetro.
- Objetos vivem na **heap**; variáveis guardam **referências**. Sem referências, o GC recolhe o objeto.
- Coloque o comportamento **junto dos dados** que ele protege (*Tell, Don't Ask*).
