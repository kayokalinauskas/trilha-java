## Stream Gatherers (Java 24)

Até o Java 23, as operações intermediárias eram fixas: `map`, `filter`, `flatMap`… Não havia como fazer, por exemplo, "janelas de 3 elementos" sem sair da Stream. O Java 24 (JEP 485) trouxe `Stream.gather(...)` e a classe `Gatherers` com operações prontas:

```java
import java.util.stream.Gatherers;

// Janelas fixas: lotes de 100 para enviar a uma API
List<List<Pedido>> lotes = pedidos.stream()
        .gather(Gatherers.windowFixed(100))
        .toList();

// Janelas deslizantes: média móvel de 3 dias
List<Double> medias = vendasDiarias.stream()
        .gather(Gatherers.windowSliding(3))
        .map(janela -> janela.stream().mapToDouble(Double::doubleValue).average().orElse(0))
        .toList();

// scan: todos os resultados intermediários de uma acumulação (saldo após cada lançamento)
List<BigDecimal> saldos = lancamentos.stream()
        .gather(Gatherers.scan(() -> BigDecimal.ZERO, BigDecimal::add))
        .toList();

// fold: acumula em um único resultado (como reduce, mas o tipo do acumulador pode ser outro)
Optional<String> csv = ids.stream()
        .gather(Gatherers.fold(() -> "", (acc, id) -> acc.isEmpty() ? id : acc + "," + id))
        .findFirst();
```

Gatherers exigem **Java 24+**. As soluções dos exercícios deste módulo não dependem deles (funcionam no Java 21), mas os desafios opcionais sugerem onde usá-los. Também é possível escrever um `Gatherer` próprio, implementando a interface `java.util.stream.Gatherer`, para operações com estado como "remover duplicatas consecutivas".

## Pattern matching para processar eventos

No módulo 02 você usou `sealed` + `switch` para regras de frete. O mesmo par brilha para **eventos**: fatos imutáveis que aconteceram no sistema.

```java
public sealed interface EventoConta {
    String contaId();
    Instant momento();

    record ContaAberta(String contaId, Instant momento, String titular) implements EventoConta { }
    record Deposito(String contaId, Instant momento, BigDecimal valor) implements EventoConta { }
    record Saque(String contaId, Instant momento, BigDecimal valor) implements EventoConta { }
    record ContaBloqueada(String contaId, Instant momento, String motivo) implements EventoConta { }
}
```

Records aninhados na interface deixam a hierarquia inteira em um só arquivo, e o `permits` fica implícito (o compilador infere as subclasses declaradas no mesmo arquivo).

O coração é uma **função pura** `(estado, evento) → novo estado`:

```java
private static EstadoConta aplicar(EstadoConta e, EventoConta evento) {
    return switch (evento) {
        case ContaAberta(var conta, var momento, String titular) -> new EstadoConta(conta, titular, ZERO, false, 1);
        case Deposito d -> e.comSaldo(e.saldo().add(d.valor()));
        case Saque s -> e.comSaldo(e.saldo().subtract(s.valor()));
        case ContaBloqueada b -> e.bloqueada();
    };
}
```

Reconstruir é **aplicar em sequência**, um "fold" (ou "reduce") dos eventos sobre o estado inicial. Vantagens: histórico completo para auditoria (essencial em fintechs), capacidade de reconstruir o estado em qualquer momento do passado e de criar novas "projeções" a partir dos mesmos eventos. Custos: mais complexidade e a necessidade de *snapshots* quando os eventos são muitos. Você vai rever eventos no módulo 12, com Kafka.

O exercício 04.04 pede exatamente isso: reconstruir contas a partir de um histórico, com `sealed`, `switch` exaustivo, *record patterns* e Streams.

## Guia de legibilidade

O estilo funcional é uma ferramenta, não uma religião. Algumas regras práticas que times experientes seguem:

<Comparar antes="Esperto demais" depois="Legível">
```java
return pedidos.stream().filter(p -> p.status() == PAGO
    && p.data().getYear() == ano).collect(groupingBy(
    p -> p.cliente().toUpperCase(), TreeMap::new,
    collectingAndThen(reducing(ZERO, Pedido::valor,
    BigDecimal::add), v -> v.setScale(2, HALF_EVEN))))
    .entrySet().stream().filter(e -> e.getValue()
    .compareTo(MIL) > 0).map(Map.Entry::getKey).toList();
```

```java
Map<String, BigDecimal> totalPorCliente = pedidos.stream()
        .filter(pagosNoAno(ano))
        .collect(groupingBy(Pedido::cliente, TreeMap::new, SOMA_VALOR));

return clientesAcimaDe(totalPorCliente, MIL);
```
</Comparar>

1. **Uma operação por linha**, alinhadas pelo ponto.
2. **Extraia predicados e coletores com nome** (`pagosNoAno(ano)`, `SOMA_VALOR`).
3. **Quebre pipelines longos** em etapas com variáveis de nome significativo.
4. **Method references** quando deixam mais claro; lambda quando o nome do método não diz tudo.
5. Se o laço `for` fica mais claro, **use o laço**.

## Resumo

- **Gatherers** (Java 24): `windowFixed`, `windowSliding`, `scan`, `fold` e gatherers próprios.
- `sealed` + records + `switch` exaustivo modelam e processam **eventos** com segurança.
- **Event sourcing** = estado derivado de um fold de eventos por uma função pura.
- Estilo funcional com legibilidade: uma operação por linha, nomes para predicados e coletores, laço quando for mais claro.
