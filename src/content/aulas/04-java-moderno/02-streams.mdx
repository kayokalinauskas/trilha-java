Uma **Stream** é uma forma **declarativa** de processar coleções: você descreve **o que** quer ("os pedidos pagos, convertidos em valor, somados") em vez de **como** percorrer ("crie um acumulador, faça um for, teste o status…"). Bem usada, deixa o código mais curto e mais legível. Mal usada, vira um enigma de uma linha só.

## O pipeline

```java
BigDecimal faturamento = pedidos.stream()        // 1. fonte
        .filter(Pedido::pago)                    // 2. intermediária: mantém só os pagos
        .map(Pedido::valor)                      // 2. intermediária: Pedido → BigDecimal
        .reduce(BigDecimal.ZERO, BigDecimal::add); // 3. terminal: combina tudo em um valor
```

- **Fonte**: `colecao.stream()`, `Arrays.stream(array)`, `Stream.of(a, b, c)`, `IntStream.range(0, 10)`, `Files.lines(caminho)`.
- **Operações intermediárias** devolvem outra Stream: `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `skip`, `peek`.
- **Operação terminal** produz o resultado: `toList`, `collect`, `forEach`, `reduce`, `count`, `sum`, `min`, `max`, `findFirst`, `anyMatch`, `allMatch`, `noneMatch`.

## Preguiçosa e com curto-circuito

As operações intermediárias **não fazem nada** até a terminal ser chamada. E cada elemento percorre o pipeline **inteiro** antes do próximo:

```java
Optional<Pedido> primeiroGrande = pedidos.stream()
        .filter(p -> p.valor().compareTo(MIL) > 0)
        .findFirst();
```

Se o terceiro pedido já passa no filtro, o quarto nunca é avaliado. `findFirst`, `anyMatch`, `limit` e similares são **curto-circuito**: param assim que têm a resposta. É por isso que uma Stream pode percorrer até uma fonte infinita (`Stream.iterate(1, n -> n + 1).limit(10)`).

## As operações que você mais vai usar

```java
List<String> clientesVip = pedidos.stream()
        .filter(p -> p.valor().compareTo(MIL) >= 0)
        .map(Pedido::cliente)
        .distinct()
        .sorted()
        .toList();

boolean temCancelado = pedidos.stream().anyMatch(p -> p.status() == CANCELADO);
long pendentes = pedidos.stream().filter(p -> p.status() == PENDENTE).count();

Optional<Pedido> maior = pedidos.stream().max(Comparator.comparing(Pedido::valor));
List<Pedido> top3 = pedidos.stream()
        .sorted(Comparator.comparing(Pedido::valor).reversed())
        .limit(3)
        .toList();
```

### `map` versus `flatMap`

`map` transforma **um em um**. `flatMap` transforma **um em vários** e achata:

```java
// Cada pedido tem vários itens. Quero TODOS os itens de TODOS os pedidos:
List<Item> itens = pedidos.stream()
        .flatMap(p -> p.itens().stream())      // Stream<Pedido> → Stream<Item>
        .toList();

// Com map, eu teria uma Stream<List<Item>> — uma lista de listas.
```

### `reduce`

`reduce` combina todos os elementos em um só, com um **valor inicial** (a identidade) e uma **função associativa**:

```java
BigDecimal total = valores.stream().reduce(BigDecimal.ZERO, BigDecimal::add);
```

Para somas de números primitivos, prefira as **streams de primitivos**.

## Streams de primitivos

`IntStream`, `LongStream` e `DoubleStream` evitam o custo de embrulhar cada número em `Integer`/`Long`/`Double` e têm métodos estatísticos prontos:

```java
int totalItens = pedidos.stream().mapToInt(Pedido::quantidade).sum();
OptionalDouble media = notas.stream().mapToDouble(Double::doubleValue).average();
IntSummaryStatistics stats = pedidos.stream().mapToInt(Pedido::quantidade).summaryStatistics();
// stats.getMin(), getMax(), getAverage(), getSum(), getCount()

IntStream.rangeClosed(1, 12).mapToObj(mes -> YearMonth.of(2026, mes)).toList();
```

`BigDecimal` não tem stream primitiva: para dinheiro, use `map(...).reduce(ZERO, BigDecimal::add)`.

## Regras de ouro

<Comparar antes="Evite" depois="Prefira">
```java
List<String> nomes = new ArrayList<>();
pedidos.stream()
       .filter(Pedido::pago)
       .forEach(p -> nomes.add(p.cliente()));

Stream<Pedido> s = pedidos.stream();
s.count();
s.findFirst();   // IllegalStateException
```

```java
List<String> nomes = pedidos.stream()
       .filter(Pedido::pago)
       .map(Pedido::cliente)
       .toList();

long total = pedidos.stream().count();
Optional<Pedido> p = pedidos.stream().findFirst();
```
</Comparar>

1. **Sem efeitos colaterais** nas intermediárias. `forEach` que alimenta uma lista externa é um laço disfarçado — e quebra com streams paralelas. Use um coletor.
2. **Uma Stream, um uso.** Depois da operação terminal, ela está fechada.
3. **`Stream.toList()`** (Java 16+) devolve uma lista **imutável**. É o que você quer quase sempre.
4. **Uma operação por linha**, alinhadas pelo ponto. Pipelines de 12 operações pedem métodos auxiliares com nome.

## Quando NÃO usar Streams

Streams não são "o jeito moderno" que substitui todo laço. Prefira um `for` quando:

- você precisa **sair no meio** com lógica complexa, ou de **índices** (comparar com o elemento anterior, como no exercício 01.03);
- o corpo lança **exceções checked** (lambdas não podem lançá-las sem embrulhar);
- o laço **modifica** estruturas externas por natureza;
- a versão com Stream ficou **mais difícil de ler** que o laço.

<Callout tipo="atencao" titulo="parallelStream não é turbo">
`parallelStream()` divide o trabalho entre threads do `ForkJoinPool` comum. Em coleções pequenas, fica **mais lento** (o custo de dividir é maior que o ganho); com operações bloqueantes (I/O), pode travar outras partes da aplicação que usam o mesmo pool. Só use depois de medir, em trabalho CPU-bound sobre coleções grandes.
</Callout>

## Resumo

- Pipeline = **fonte → intermediárias (preguiçosas) → terminal**.
- `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit` + `toList`, `reduce`, `count`, `anyMatch`, `findFirst`.
- Streams de primitivos (`mapToInt`, `sum`, `summaryStatistics`) para números; `reduce(ZERO, add)` para `BigDecimal`.
- Sem efeitos colaterais, uma Stream por uso, `toList()` imutável.
- Laço comum quando há índices, exceções checked ou quando fica mais legível.
