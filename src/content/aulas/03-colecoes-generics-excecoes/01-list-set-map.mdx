Quase todo código de backend manipula grupos de coisas: os itens de um pedido, os clientes de uma cidade, o total de vendas por produto. O **Java Collections Framework** oferece as estruturas para isso. Escolher a certa deixa o código mais simples, mais correto e, muitas vezes, milhares de vezes mais rápido.

| Interface | Pergunta que responde | Exemplo de negócio |
|---|---|---|
| **`List`** | "Quais, em que ordem?" (aceita repetidos) | Itens de um pedido, histórico do extrato |
| **`Set`** | "Este elemento já existe?" (sem repetidos) | CPFs já cadastrados, tags de um produto |
| **`Map`** | "Qual o valor para esta chave?" | Estoque por SKU, pedidos por cliente |
| **`Deque`** | "Qual o próximo?" (fila ou pilha) | Fila de processamento, histórico de "desfazer" |

Repare que `Map` **não** é uma `Collection`: ele guarda pares chave → valor.

## `List`

```java
List<String> itens = new ArrayList<>();
itens.add("café");
itens.add("filtro");
itens.add("café");               // repetido: tudo bem
itens.get(0);                    // "café"
itens.size();                    // 3
itens.contains("filtro");        // true (percorre a lista: O(n))
itens.remove("café");            // remove a PRIMEIRA ocorrência
itens.indexOf("café");           // 1
```

`ArrayList` é a escolha padrão. `LinkedList` quase nunca vale a pena (a próxima aula explica o porquê).

## `Set`

```java
Set<String> cpfs = new HashSet<>();
cpfs.add("52998224725");         // true
cpfs.add("52998224725");         // false: já existia
cpfs.contains("52998224725");    // true, em tempo constante (O(1))
```

- **`HashSet`**: o mais rápido, sem ordem garantida.
- **`LinkedHashSet`**: mantém a **ordem de inserção**.
- **`TreeSet`**: mantém os elementos **ordenados**.

O `Set` decide o que é "repetido" usando `equals` e `hashCode` — tema da aula 3, e o coração do exercício 03.01.

## `Map`

```java
Map<String, Integer> estoque = new HashMap<>();
estoque.put("CAFE-500", 12);
estoque.put("FILTRO-102", 0);
estoque.put("CAFE-500", 15);             // substitui o valor anterior

estoque.get("CAFE-500");                  // 15
estoque.get("NAO-EXISTE");                // null (!)
estoque.getOrDefault("NAO-EXISTE", 0);    // 0
estoque.containsKey("FILTRO-102");        // true

for (Map.Entry<String, Integer> e : estoque.entrySet()) {
    System.out.println(e.getKey() + " → " + e.getValue());
}
```

### Os métodos que substituem dez linhas

```java
// Contar ocorrências
Map<String, Integer> contagem = new HashMap<>();
for (String palavra : palavras) {
    contagem.merge(palavra, 1, Integer::sum);      // insere 1 ou soma 1
}

// Agrupar: pedidos por cliente
Map<String, List<Pedido>> porCliente = new HashMap<>();
for (Pedido p : pedidos) {
    porCliente.computeIfAbsent(p.clienteId(), id -> new ArrayList<>()).add(p);
}
```

- **`merge(chave, valor, função)`**: se a chave não existe, insere o valor; se existe, combina o atual com o novo pela função.
- **`computeIfAbsent(chave, criador)`**: devolve o valor da chave, criando-o com a função se ainda não existir.

Esses dois métodos aparecem em todo código de agregação. O exercício 03.02 usa `merge` para montar um ranking.

## `Deque`: fila e pilha

```java
Deque<String> fila = new ArrayDeque<>();
fila.offer("pedido-1");      // entra no fim
fila.offer("pedido-2");
fila.poll();                 // "pedido-1" — sai do início (FIFO)

Deque<String> pilha = new ArrayDeque<>();
pilha.push("tela-1");
pilha.push("tela-2");
pilha.pop();                 // "tela-2" — último a entrar, primeiro a sair (LIFO)
```

Use `ArrayDeque` para os dois papéis. A classe `Stack` é antiga e sincronizada à toa — evite.

## Coleções imutáveis

```java
List<String> formas = List.of("PIX", "CARTAO", "BOLETO");
Set<Integer> ddds = Set.of(11, 21, 31);
Map<String, BigDecimal> taxas = Map.of("PIX", ZERO, "BOLETO", new BigDecimal("3.50"));

formas.add("CRIPTO");        // UnsupportedOperationException
List.of("a", null);          // NullPointerException: não aceita null
List<String> copia = List.copyOf(outraLista);  // cópia imutável
```

Coleções imutáveis são perfeitas para constantes, retornos de métodos (o extrato do exercício 02.01) e cópias defensivas.

<Callout tipo="atencao" titulo="Imutável não é o mesmo que 'não modificável'">
`Collections.unmodifiableList(lista)` devolve uma **visão** somente leitura: você não altera por ela, mas se a `lista` original mudar, a visão também muda. `List.copyOf` cria uma **cópia** que nunca muda. Para cópias defensivas, prefira `List.copyOf`.
</Callout>

## Modificar durante a iteração

```java
for (Pedido p : pedidos) {
    if (p.cancelado()) {
        pedidos.remove(p);       // ConcurrentModificationException
    }
}
```

O for-each usa um `Iterator` por baixo, e a lista "percebe" que foi alterada por fora. As formas corretas:

```java
pedidos.removeIf(Pedido::cancelado);               // a mais simples

Iterator<Pedido> it = pedidos.iterator();          // controle manual
while (it.hasNext()) {
    if (it.next().cancelado()) {
        it.remove();                               // remove pelo próprio iterator
    }
}
```

## Resumo

- `List` (ordem e repetidos), `Set` (unicidade), `Map` (chave → valor), `Deque` (fila/pilha).
- Padrões: `ArrayList`, `HashSet`, `HashMap`, `ArrayDeque`. Use as variantes `Linked*` para ordem de inserção e `Tree*` para ordem classificada.
- `merge` e `computeIfAbsent` resolvem contagens e agrupamentos em uma linha.
- `List.of`/`List.copyOf` para coleções imutáveis; `removeIf` para remover durante a iteração.
