Duas soluções podem dar o mesmo resultado nos testes e ter desempenhos radicalmente diferentes em produção. Com 100 registros, tanto faz. Com 1 milhão, uma responde em milissegundos e a outra derruba o servidor. A notação **Big-O** é a ferramenta para prever isso **antes** de acontecer.

## Big-O em uma frase

Big-O descreve **como o tempo (ou a memória) cresce quando a entrada cresce**. Não mede segundos; mede a **forma** da curva.

| Notação | Nome | Exemplo | 1 mil itens | 1 milhão de itens |
|---|---|---|---|---|
| O(1) | constante | `array[i]`, `hashMap.get(k)` | 1 passo | 1 passo |
| O(log n) | logarítmica | busca binária, `TreeMap.get` | ~10 | ~20 |
| O(n) | linear | percorrer a lista, `list.contains` | 1 mil | 1 milhão |
| O(n log n) | — | ordenar (`list.sort`) | ~10 mil | ~20 milhões |
| O(n²) | quadrática | laço dentro de laço sobre os mesmos dados | 1 milhão | **1 trilhão** |

A última linha é a que derruba sistemas. E ela aparece com muita facilidade:

<Comparar antes="O(n²) sem perceber" depois="O(n)">
```java
List<String> jaVistos = new ArrayList<>();
for (Pedido p : pedidos) {                    // n vezes
    if (!jaVistos.contains(p.clienteId())) {  // contains: O(n)
        jaVistos.add(p.clienteId());
    }
}
```

```java
Set<String> jaVistos = new HashSet<>();
for (Pedido p : pedidos) {                    // n vezes
    jaVistos.add(p.clienteId());              // O(1)
}
```
</Comparar>

Com 200 mil pedidos, a versão da esquerda faz na ordem de **20 bilhões** de comparações; a da direita, 200 mil operações. A troca de uma palavra (`ArrayList` → `HashSet`) muda tudo.

- **`get(i)`: O(1).** Acesso direto à posição do array.
- **`add(x)` no fim: O(1) amortizado.** Quando o array enche, a lista cria um novo, cerca de 1,5 vez maior, e copia tudo. Isso é raro o bastante para que, **em média**, cada `add` custe O(1).
- **`add(0, x)` ou `remove(0)`: O(n).** Todos os elementos precisam andar uma posição.
- **`contains(x)`: O(n).** Não há atalho: é preciso olhar um por um.

<Callout tipo="dica">
Se você sabe quantos elementos vai inserir, diga ao construtor: `new ArrayList<>(pedidos.size())`. Isso evita todas as cópias intermediárias.
</Callout>

## E a `LinkedList`?

Na teoria, a `LinkedList` (lista duplamente encadeada) insere e remove no meio em O(1). Na prática:

- para chegar ao meio, ela precisa **percorrer os nós**: O(n);
- cada nó é um objeto separado na memória, o que é **péssimo para o cache do processador**;
- ela usa várias vezes mais memória que um `ArrayList`.

Resultado: `ArrayList` ganha na grande maioria dos casos reais. Para filas, use `ArrayDeque`. O próprio autor da `LinkedList`, Joshua Bloch, brincou publicamente que nunca a usa.

1. O `hashCode()` da chave é transformado em um **índice de bucket**.
2. O `HashMap` vai direto ao bucket: O(1).
3. Se mais de uma chave cair no mesmo bucket (**colisão**), ele compara com `equals()` até achar a certa.
4. Quando o mapa passa de 75% de ocupação (*load factor* 0,75), ele dobra o número de buckets e redistribui as chaves (*rehash*).
5. Desde o Java 8, um bucket com muitas colisões vira uma **árvore**, então o pior caso é O(log n), não O(n).

Duas consequências práticas:

- **`hashCode` ruim = `HashMap` lento.** Se todas as chaves tiverem o mesmo hash, tudo cai no mesmo bucket.
- **`equals`/`hashCode` inconsistentes = `HashMap` errado.** Você coloca uma chave e não consegue achá-la de volta. A próxima aula é inteira sobre isso.

## Tabela de referência

| Operação | `ArrayList` | `LinkedList` | `HashSet`/`HashMap` | `TreeSet`/`TreeMap` | `ArrayDeque` |
|---|---|---|---|---|---|
| Acesso por índice | **O(1)** | O(n) | — | — | — |
| Adicionar no fim | **O(1)*** | O(1) | **O(1)*** | O(log n) | **O(1)*** |
| Adicionar/remover no início | O(n) | O(1) | — | — | **O(1)*** |
| Buscar (`contains`/`get`) | O(n) | O(n) | **O(1)*** | O(log n) | O(n) |
| Iterar em ordem | inserção | inserção | nenhuma | **classificada** | inserção |

\* amortizado ou em média.

## Escolha pela operação dominante

Antes de escolher, pergunte: **qual operação o código vai fazer milhões de vezes?**

- "Existe?" → `HashSet`.
- "Qual o valor para X?" → `HashMap`.
- "Preciso dos itens ordenados o tempo todo" ou "qual o menor maior que X?" → `TreeMap`/`TreeSet`.
- "Percorrer na ordem em que chegaram" → `ArrayList` ou `LinkedHashMap`.
- "Próximo da fila" → `ArrayDeque`; "o de maior prioridade" → `PriorityQueue`.

## Resumo

- Big-O descreve **como o custo cresce**. Cuidado com O(n²): laço dentro de laço ou `contains` em lista dentro de laço.
- `ArrayList`: índice O(1), `contains` O(n). `LinkedList` quase nunca compensa.
- `HashMap`/`HashSet`: O(1) em média, **se** `hashCode` e `equals` estiverem corretos.
- `TreeMap`/`TreeSet`: O(log n) com ordem classificada.
- Escolha pela **operação dominante** do seu problema.
